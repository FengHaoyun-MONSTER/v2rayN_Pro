# 一键网络设置与自动恢复设计

## 目标

面向不了解代理、节点和系统代理概念的用户，软件负责判断网络状态并完成
更新订阅、真延迟测试、排序、选点、启动核心、设置系统代理和联网验证。

本功能第一阶段只在 Windows 主界面展示和自动运行；网络探测、订阅工作流
和快照逻辑位于 `ServiceLib`，便于后续复用到 Desktop 平台。

## 首页状态

| 状态 | 颜色 | 文案 | 行为 |
| --- | --- | --- | --- |
| 可用 | 绿色 | 当前网络可用 | 无 |
| 修复中/检查中 | 黄色 | 当前网络不可用，正在自动修复 | 禁用重复操作 |
| 已修复 | 蓝色 | 当前网络已自动修复 | 显示修复时间，保留 10 分钟 |
| 无节点 | 红色 | 无可用节点，请联系客服 | 打开支持链接；没有链接时编辑当前订阅 |
| 本机断网 | 灰色 | 本机网络不可用，请检查 Wi-Fi 或网线 | 不更新订阅 |

## 一键设置网络

1. 不使用代理访问多个独立联网探测地址，确认本机有网络。
2. 通过当前本地 SOCKS 端口执行真延迟测试。
3. 当前延迟为正且不超过 500 ms 时，设置自动系统代理并通过本地代理访问
   `https://www.google.com/generate_204`。
4. 当前节点延迟为 `-1`、超过 500 ms 或 Google 验证失败时，执行
   “更新全部订阅（不使用代理）”。
5. 对实际更新涉及的每个订阅分组执行真延迟测试。
6. 每个分组按有效正延迟升序排列；未测试的 `0` 在有效结果之后，
   失败的 `-1` 排在最后。
7. 新节点最低延迟低于当前节点、当前节点不存在或当前延迟无效时才切换。
8. 启动主核心成功后设置“自动配置系统代理”，再执行 Google 204 验证。

普通订阅测速不删除任何节点。`-1` 或大于 500 ms 的删除规则仅用于
“以此节点自动生成最优节点”产生、且 Remark 为“最优节点”的配置。

## 自动恢复

- Windows 启动服务 15 秒后开始检查，此后每分钟检查一次。
- 连续 3 次代理联网失败才进入自动修复，降低瞬时抖动造成的误切换。
- 自动修复先测试现有订阅节点并尝试切换；仍不可用时再直连更新全部订阅。
- 所有恢复任务和订阅任务分别通过信号量串行化，避免并发测速、重复更新。
- 主核心启动失败时立即撤销操作系统代理，再进入恢复流程。
- 软件退出时继续复用官方 `AppManager.AppExitAsync` 清理系统代理。

## 最后可用快照

- 快照目录：`guiConfigs/subscriptionSnapshots`。
- 文件名使用订阅 ID 的 SHA-256，禁止订阅 ID 参与路径拼接。
- 只保存 `IsSub=true` 的订阅节点及其 `ProfileExItem` 测速数据。
- 至少有一个成功真延迟结果，或快照包含当前活动节点时才覆盖旧快照。
- 更新失败或新节点全部不可用时，只恢复对应订阅节点；手工节点不受影响。

## 主要代码

- `ServiceLib/ViewModels/MainWindowViewModel.cs`：工作流和状态机
- `ServiceLib/ViewModels/ProfilesViewModel.cs`：逐订阅真延迟与排序
- `ServiceLib/Handler/ConnectionHandler.cs`：直连和代理联网验证
- `ServiceLib/Handler/SubscriptionSnapshotHandler.cs`：快照与恢复
- `ServiceLib/Common/LatencySortHelper.cs`：排序和切换决策
- `v2rayN/Views/SubscriptionInfoView.xaml`：Windows 首页状态 UI

## 回归重点

- 首次添加订阅仍能自动完成更新、真延迟、排序、激活和系统代理设置。
- 手动、托盘、定时和自动修复更新均进入同一订阅工作流。
- 活动节点且自动系统代理已开启时，普通更新不强制切换。
- 一键设置网络遵循“新节点更快才切换”的比较规则。
- 主核心失败后操作系统代理不保留失效端口。
- 快照恢复不会删除手工配置或其他订阅的节点。
