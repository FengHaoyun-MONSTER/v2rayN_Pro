# v2rayN CloudflareST 自动优选设计说明

## 目标

在 Windows WPF 版主界面节点列表中，为模板节点 `cfth.thinderbox.uk` 增加一键自动生成 Cloudflare 优选节点能力。流程结束后沿用现有真延迟排序与自动设置首个节点为活动节点逻辑。

## 实现范围

- 入口仅接入 Windows WPF 版 `ProfilesView` 右键菜单。
- 仅当选中节点 `Address == "cfth.thinderbox.uk"` 时显示入口。
- 本版只做本地内置 `CloudflareST` 检测与调用，完整备用源更新器后续实现。
- 旧节点清理仅处理当前分组内 `Remarks == "最优节点"` 的节点。

## 流程

1. 用户右键模板节点，点击 `以此节点自动生成优选节点`。
2. ViewModel 设置优选运行状态并拦截重复触发。
3. 读取当前分组旧优选节点，执行现有真延迟测试。
4. 删除延迟为 `-1` 或 `> 500ms` 的旧优选节点，保留 `<= 500ms` 的节点。
5. 计算补充数量：`100 - 保留数量`。
6. 静默运行内置 `CloudflareST`，使用默认推荐参数，并额外指定：
   - `-n 1000`：使用 CloudflareST 文档标注的最大延迟测速并发，不减少 `ip.txt` 覆盖面。
   - `-dt 3`：单个 IP 下载测速最长 3 秒。
   - `-debug`：输出下载测速失败原因，方便在 v2rayN 消息视图排查。
   - `-p <补充数量>`：打印结果到 v2rayN 日志；进程 stdin 被重定向并关闭，避免 Windows 结束等待回车。
   - `-dn 10`：只对前 10 个低延迟候选做下载测速，避免 100 个下载测速串行导致速度明显慢于手动运行。
   - `-f <内置 ip.txt>`：使用随包内置 Cloudflare IPv4 段。
   - `-o <临时 result.csv>`：结果写入 v2rayN 临时目录。
7. 读取 CSV，按下载速度降序、平均延迟升序选取候选 IP，克隆模板节点生成新节点。这样节点池仍可补齐 100 个，但下载测速耗时接近 CloudflareST 默认手动运行。
8. 新节点写入规则：
   - `Remarks = "最优节点"`
   - `Address = 优选 IP`
   - Host/SNI/路径/端口/UUID 等配置继承模板节点。
9. 刷新当前分组，执行真延迟测试，按延迟升序排序，设置第一条可用节点为活动节点。

自动优选流程内部的真延迟测试静默 core 进程明细日志，避免 Xray 的连接接受日志和 TLS 失败日志刷屏；用户仍会看到阶段开始、完成、保留/删除/新增数量等关键日志。

## CloudflareST 集成

`CloudflareST.exe` 的默认输出 CSV 第一列为 IP，第七列为地区码。当前功能只需要 IP 生成节点，地区列继续由现有真延迟探测逻辑在后续测速中填充。当前不会缩小内置 `ip.txt`，延迟测速候选覆盖面保持 CloudflareST 默认展开结果，只提高并发来缩短等待。

运行方式使用 `ProcessStartInfo`：

- `UseShellExecute = false`
- `CreateNoWindow = true`
- `WindowStyle = Hidden`
- 重定向标准输出和错误输出

这样不会弹出黑色控制台窗口，且工具路径解析、进程启动状态、标准输出、标准错误、进度条刷新、退出码、CSV 解析结果都会同步写入 v2rayN 消息视图和文件日志。进度条使用回车刷新时按约 1 秒节流输出，避免消息视图被高频刷屏卡住。若 CloudflareST 在下载测速阶段长时间没有输出，v2rayN 会每 10 秒输出一次进程心跳，说明进程仍在运行。

## 并发控制

ViewModel 使用 `IsCloudflareOptimizing` 状态控制菜单可用性。运行期间再次触发会直接提示正在优选，避免启动多个 CloudflareST 进程。

## 失败策略

- 未找到内置 `CloudflareST` 或 `ip.txt`：提示缺少程序/数据，不修改节点。
- 旧节点测速失败：只删除明确得到 `-1` 或 `>500ms` 的旧优选节点。
- CloudflareST 无结果：提示失败，不生成节点。
- 生成节点失败：保留已存在节点，不做回滚。
