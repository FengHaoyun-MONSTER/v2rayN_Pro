# 自动真延迟排序与清理范围设计

## 目标

将普通订阅自动处理与 Cloudflare 最优节点生成后的处理分离，避免普通订阅节点因延迟失败或超过阈值被自动删除。

## 普通订阅流程

新增订阅后执行：

1. 自动更新当前订阅（不通过代理）。
2. 对当前订阅分组执行真延迟测试。
3. 按延迟从低到高排序，`Delay == -1` 固定排在最后。
4. 将排序后的第一个有效节点设置为活动节点。

该流程不删除任何节点。手动真延迟测试同样不触发节点删除。

## Cloudflare 最优节点流程

保留生成前清理旧最优节点的原有逻辑。CloudflareST 生成节点后执行：

1. 对当前分组执行真延迟测试。
2. 仅从本次测试集合中筛选 `Remarks == "最优节点"` 的配置。
3. 删除 `Delay == -1` 或 `Delay > 500` 的最优节点。
4. 按延迟从低到高排序，将 `Delay == -1` 排在最后。
5. 将排序后的第一个有效节点设置为活动节点。

删除前同时校验测试输入与数据库回读配置的备注，防止同组普通订阅节点被误删。
